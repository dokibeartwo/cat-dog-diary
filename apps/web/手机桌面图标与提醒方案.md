# 手机主屏幕图标与提醒方案

2026-10-09。采用同一网页 + 主屏幕图标（逐步完善 PWA），不开发新的 Android／iOS 原生客户端，不要求用户重新申请 Supabase。

## 第一阶段：点小熊图标打开网页

现有网页已经提供 manifest（standalone、相对 start_url/scope）和 apple-touch-icon，复用现有小熊图标。入口保持：

https://dokibeartwo.github.io/cat-dog-diary/

- iPhone：用 Safari 打开 → 分享 → 添加到主屏幕；系统若显示“作为网页 App 打开”，将其开启 → 添加。
- 安卓：优先用 Chrome 打开 → 右上角菜单 → 添加到主屏幕／安装应用／安装并创建快捷方式。名称随浏览器版本不同。
- 安卓自带浏览器若支持“添加到桌面”，可先创建网址快捷方式；不能保证独立窗口、安装提示及未来推送能力。图标打开即可满足本阶段要求。
- 不需要 APK、IPA、应用商店或电脑持续开机。需要手机网络能访问网页及现有同步后端。
- 从图标启动后若未登录，正常使用同一邮箱重新登录；不要假定 Safari 标签页和主屏幕 App 一定共享本地会话，也不要拷贝浏览器令牌。
- 验收：图标正确、启动 URL 不离开 /cat-dog-diary/、六主题与手机布局正常、同账号能恢复云端任务、新增任务自动同步到电脑。

图标不等于离线启动或后台提醒；目前仍未注册 Service Worker，关闭网页／锁屏后不保证计时和同步。

## 第二阶段：网页前台提醒

保留已有的页面内全屏提醒，新增明确的“启用声音／震动”和“测试提醒”入口。首次点击时解锁支持的音频能力；震动按浏览器能力检测，不显示虚假的“已震动成功”。设备偏好只保存在本设备，不随账号同步。

- 安卓支持的浏览器：尝试页面震动；无硬件、权限／系统限制、浏览器不支持时给出文字反馈。
- iPhone Safari：不支持 navigator.vibrate 页面震动接口，使用页面大屏提示与可用声音，不承诺网页强制震动。
- 真正的浏览器全屏只能由用户点击触发；到点自动展示的是页面内覆盖层，不跨到别的 App 或锁屏上。
- 勿扰、总开关、已完成／已删除任务、重复和稍后提醒沿用既有规则；同一提醒不因每秒 tick／同步重复响铃。
- 页面恢复前台后核对真实时间，避免一次补响大量已过期提醒。

## 第三阶段：后台／锁屏系统通知

采用标准 Service Worker + Push API + Notifications API + 服务端提醒调度。沿用同一个 Supabase 项目，新增订阅与调度模块。仅靠网页定时器不够；不把离线缓存和后台通知混为一谈。

服务端部署前先提交迁移预览及回滚方案；不在本次前台提醒更新中自动部署。

设计要求：

1. 用户在每台手机主动开启通知，独立保存订阅；iPhone 使用 iOS 16.4 或以上的主屏幕 Web App。
2. 订阅记录按账号和设备隔离，默认不在锁屏通知里暴露任务标题，用户可自行开启详细内容。
3. 服务端只读取任务／习惯提醒规则和完成状态，按时区、勿扰及用户设备偏好生成到期通知，不同步“正在弹哪个窗口”或当前专注显示状态。
4. 同一规则版本、发生时刻及设备形成唯一发送键，防重复。修改、完成、删除、撤销订阅和账号删除要使旧通知失效；网络晚到的通知设合理过期时间。
5. 退出账号时解除该设备旧账号订阅；换账号不得继续显示旧账号任务。失败订阅清理，发送失败有限退避。
6. VAPID 私钥及服务端特权凭据仅留服务端秘密存储；公开网页、Windows 成品与 Git 不包含私钥。不要求用户粘贴这些秘密到对话中。
7. 点击系统通知打开当前网页版并重新核对登录账号及任务存在状态，再显示提醒详情；不在通知里直接执行破坏性操作。
8. 逐台真机验收：锁屏、切换 App、冷启动、勿扰、断网后重连、点击跳转、完成／删除后不再发送、同账号多设备与换账号隔离。推送受网络、操作系统和浏览器服务影响，不能保证精确到秒。

苹果的系统推送是否响铃／震动由系统设置决定；安卓自带浏览器和推送通道在不同手机／网络条件下可能不同，未通过实测时明确标记为“仅支持前台提醒”。不承诺跨应用强制全屏、绕过勿扰或强制震动。

## 本轮交付边界

2026-10-09 已实现第二阶段前台代码：短提示音、可用震动、即时按钮反馈、拒绝与超时提示、重复提醒去重、积压限频、隐藏或换账号取消反馈。已有页面内大屏和提醒规则保持不变，新增设置 → 手机提醒设置入口及主屏幕添加说明。

声音和震动默认关闭，只在当前浏览器保存布尔选项，不上传云端。声音需要本次页面的用户操作来启用；刷新或被系统挂起后，必要时重新点击测试。自动提示不自行请求解锁音频，不在隐藏页面响铃。同一发生在当前页面生命周期内不重复播放；连续积压提醒至少间隔 5 秒才允许新的声音／震动，被限频的项仍可在页面处理，不排队补响。主动测试不受这项限频限制。

本轮不改 Windows 正式版，不读真实浏览器登录会话，不部署 Supabase 迁移。手机实际音量、震动和主屏幕启动仍需 iPhone／安卓实测；后台推送与离线冷启动没有完成。

### 后台接入检查结果与下一步

现有仓库未提供推送订阅表、VAPID 配置、Service Worker 推送处理、Edge Function 发送器或定时调度定义。现有公开 Supabase 配置仅供登录和同步，不能替代服务端发送凭据。这是仓库检查结果，不代表已经审计远端所有配置。

下一次先准备可审查的增量迁移：账号/设备订阅表（RLS）、设备通知偏好、发送去重与失效队列；使用现有任务记录，不更换同步表或清数据。新增服务端发送函数与定时任务，并提供默认关闭的功能开关。部署前确认服务端安全配置渠道；VAPID 私钥只在服务端生成并保管，不通过聊天传输。

回滚顺序：先停调度与发送开关，停止创建新订阅；保留现有任务及同步数据，不执行清库。核对订阅和队列后再决定是否移除新增对象。只有通过两种手机的锁屏、换账号、撤订阅、完成/删除失效及重复发送实测，才标记后台能力上线。
