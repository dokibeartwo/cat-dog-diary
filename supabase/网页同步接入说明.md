# 猫狗日记：从公网预览接入账号与同步

当前公网网站仍是示例预览，尚未接通真实登录或跨设备同步。这里准备的是后端初始化、权限检查和接入步骤，不能把“配置格式检查通过”当成已经能同步。

## 现在需要你做的第一步

1. 打开 [Supabase 控制台](https://supabase.com/dashboard)，登录或注册。
2. 创建专门给猫狗日记使用的新项目，名称可用 `cat-dog-diary`。先选择 Free 方案，不要开启付费附加项。免费计划有容量、暂停等限制，不应当作生产可用性保证，具体以 [官方价格页](https://supabase.com/pricing) 为准。
3. 区域选择靠近实际使用者的位置。可先考虑 Singapore；这是内测候选，国内网络是否稳定必须用你的手机实际验证，不能只凭地理距离保证。[区域说明](https://supabase.com/docs/guides/platform/regions)
4. 设置并自行保存数据库密码，不用发给助手。项目创建完成后，找到项目 URL 和 Publishable key。旧项目的 anon key 也可以；不要复制 Secret key、service_role key、数据库密码或个人管理令牌。[密钥说明](https://supabase.com/docs/guides/getting-started/api-keys)
5. 只提供上述 URL 和公开客户端 key，或者先发创建完成页面的截图。截图遮住所有私密字段。

URL 和公开 key 能让客户端连接服务，不能代替项目所有者权限，不能用来创建表。数据库初始化需你在后台执行，或另行明确授权安全的管理连接；不要为方便而把管理员密钥填进网页。

## 数据在哪里

公开网页由 GitHub Pages 托管。真正的云端数据库位于 Supabase 所选区域，不会存在你的 E 盘中。E 盘保留源码、数据库结构脚本及你主动导出的备份；浏览器另有本地副本。电脑关机后，云端同步仍可工作，但当前预览尚未连接这套服务。

## 新项目初始化

维护者先在仓库根目录运行：

```text
node supabase/scripts/prepare-bootstrap.cjs
```

生成 `supabase/generated/猫狗日记-云同步初始化.sql` 和带 SHA-256 的迁移清单。它只组合已有迁移，不访问网络，不读取正式任务，也不含密钥。

在刚创建的专用空白项目中打开 SQL Editor，粘贴整份初始化 SQL 后执行。不要分段挑选执行。脚本包含事务；出错整体回滚。如果已存在猫狗日记相关表，会主动中止，不能用它覆盖旧项目。

已有项目只能按 `supabase/migrations` 的顺序增量升级，不运行新项目初始化脚本。新增的 `20261007000000_client_privileges.sql` 仅收紧权限，不清空或改写任务。

执行 `supabase/check-readiness.sql`，应返回 14 个 `passed = true` 的结构与权限检查项。它是只读检查，不返回任务正文。该检查不能替代真实账号隔离、邮件发送和双设备测试。

## 邮箱验证码：先自己测试，再邀请朋友

在 Authentication 的 Email 设置启用邮箱认证。邮件模板应包含 `{{ .Token }}`，否则默认可能发成登录链接，而不是让用户填写的验证码。[验证码官方说明](https://supabase.com/docs/guides/auth/auth-email-passwordless)

最简模板可用：

```html
<h2>猫狗日记登录验证码</h2>
<p>你的验证码是：<strong>{{ .Token }}</strong></p>
<p>请在猫狗日记中输入。若非本人操作，请忽略此邮件。</p>
```

站点 URL 使用 `https://dokibeartwo.github.io/cat-dog-diary/`，不要保留 localhost 作为正式站点地址，也不要开放任意重定向。

重要：默认发信服务只用于有限测试，未配置自有 SMTP 时通常仅允许项目团队成员地址，且有严格发送频率限制。给朋友开放邮箱登录前必须准备合适的发信服务；不能通过关闭邮件确认、把朋友都加成后台管理员或把发送失败显示为成功来绕过。[官方 SMTP 限制与配置](https://supabase.com/docs/guides/auth/auth-smtp)

SMTP 凭据只填 Supabase 后台，不放入 GitHub、网页、聊天或备份。本轮没有注册付费邮件服务，也没有替你购买域名。

## 客户端接入与发布门槛

复制 `apps/web/.env.example` 为本地 `.env.local`，填写公开配置。可以执行 `npm run check:cloud-config`。检查会拒绝 secret/service_role、用户登录令牌、错配项目及失效 anon key；不打印 key，不发邮件，不连接云端。

这些准备不会自动启用网站账号功能。还需要把网页接入独立的正式清单存储与账号流程，完成以下验收再更新公网版本：

- 示例数据保持隔离；初次登录默认使用独立空清单，不把任何示例任务自动上传。
- 本机/云端数量预览、备份和明确确认后才允许首次合并。
- 邮箱收码、错误码、退出与账号切换；旧账号请求不能写入新账号。
- 手机与 Windows 的同账号双向同步，以及另一账号不可访问数据。
- 离线修改、重试去重、同字段冲突、删除/恢复、习惯完成事件和专注租约。
- 保留现有主题和本地数据；完成账号删除和导出验证后再邀请朋友。

当前已在本地 PostgreSQL 测试环境验证权限收紧与现有同步规则，但尚未在真实 Supabase 项目验证 Auth、SMTP、实际网络和双设备。后台通知不随账号同步自动获得，仍需另行实施和验收。
